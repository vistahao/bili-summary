## 3. 数据和凭据边界

1. 音频只上传这个 10 分钟样本，不上传原 MP4。
2. 初次比较使用百炼官方临时上传：文件保持私有，`oss://` URL 48 小时有效；它适合低频测试，但官方没有提供“完成后立即删除”的同等接口，所以不能写成即时删除。生产流程以后再评估自有私有 OSS 和显式删除。
3. 临时上传规定“上传时指定的模型必须与调用模型完全一致”，因此同一 WAV 需要分别为两个模型上传一次；不会上传原 MP4。
4. 阿里云公开 ASR 文档没有给出足够明确的内部音频保留期；测试前必须在控制台协议中核对。不要开启会保存请求和响应正文的“推理日志”。[阿里云模型监控说明](https://help.aliyun.com/zh/model-studio/model-telemetry/)
5. API Key 只放权限 `600` 的 Git 忽略文件或环境变量；不进入命令参数、日志、`source.json`、对比报告或聊天。
6. 原始厂商响应可能包含完整转写文本，属于学习成果/评测依据；验收后保存到独立成果目录并纳入成果备份，不放 Git。

## 5. 本地 CPU 基线

本地第一候选为 `whisper.cpp` 的多语种 `small` 模型：它是 OpenAI 2022 年 Whisper 的轻量 C/C++ 实现，支持纯 CPU，运行时不需要 Python 包；官方列出的模型磁盘约 466 MiB、内存约 852 MB，当前 WSL 资源可以承受。若中文术语质量明显不足，再单独评估 1.5 GiB 的 `medium`，不提前下载多个模型。

[whisper.cpp 官方说明](https://github.com/ggml-org/whisper.cpp)显示其命令行输入正好需要单声道 16 kHz、16-bit WAV，与阶段 4A 生成的测试文件一致。本地源码、构建物和模型应放在独立工具缓存中，标记为可重新下载、不备份，不污染项目 `.venv`。

只读检查发现本机没有 CMake 和 C++ 编译器，因此没有安装系统构建工具或自行编译。测试使用 `whisper.cpp` 官方 Ubuntu x64 预编译包 `b4938`，包的 SHA-256 验证为 `f4cfc1f969a13805908fb72043ce7cc896eb42e0b8afbe841dc8e7298923b061`；多语种 `small` 模型为 487,601,967 字节，SHA-256 验证为 `1be3a9b2063867b937e64e2ec7483364a79917e157fa98c5d94b5c1fffea987b`。

正式 10 分钟基线使用 8 个线程、纯 CPU、中文模式：墙钟时间 1 分 51.32 秒，平均约为音频时长的 5.4 倍速，峰值常驻内存 955,156 KiB（约 933 MiB），无交换；输出 194 个 SRT 片段，时间戳连续覆盖到 10:00.100。速度和资源占用可以作为离线兜底，但当前准确率不能直接作为默认方案：连续语句基本完整，仍出现“老舅/生育/行策”等对“老旧/声誉/行测”的同音或近音误写，以及题型术语错误。

预编译工具、模型和原始基准输出共约 501 MiB，全部位于 `/tmp/bili-summary-whisper-b4938/`，没有写入项目 `.venv` 或系统目录；它们可重新下载、不备份，系统清理 `/tmp` 后不会影响项目源代码或长期成果。正式 WAV 仍由阶段 4A 缓存管理。在线两项完成同片段人工核对前，不下载更大的 `medium` 模型。

## 6. 同片段比较方法

两项在线模型使用完全相同的 WAV；本地结果只保留为兜底参照。第一轮不使用 Paraformer 热词，不开启去语气词、时间戳校准或说话人分离；Qwen3 本身不支持热词和 Prompt。本轮按 Qwen3 官方异步示例关闭 ITN，并请求字级时间戳，先比较基础识别能力。

记录以下指标：

- 逐字核对三个各 2 分钟窗口，覆盖开头、中段和末段；记录关键事实误写数、术语错误数和遗漏数。
- 检查句级时间戳是否单调、是否能回到正确语句，抽查词级时间戳。
- 记录端到端等待时间、厂商任务 ID、计费秒数和公开价格估算；免费额度变化与实际账单不作为项目验收项。
- 记录安装体积、模型体积、峰值内存和 CPU 用时。
- 原始结果与统一 SRT 分开保存；统一转换不能覆盖厂商原始响应。

只有完成上述人工核对后才选择默认在线后端。单价更低或速度更快不能代替准确率判断。

## 7. 真实调用结果

2026-08-31 已用固定 10 分钟样本完成两项调用，成果位于 `/home/dev/bili-summary-data/模型对比/transcription-sample-语音转写-b0e3a89f22fc/`。Qwen3 返回 110 个句段、2,642 个文本字符和 2,329 个字级时间项，厂商任务处理 5.982 秒；Paraformer 返回 99 个句段、2,564 个字符和 2,301 个词级时间项，厂商任务处理 6.663 秒。两者时间戳均单调、无相邻重叠并覆盖到约 10 分钟。

三个 2 分钟窗口的工具侧抽查中，Qwen3 对“老旧”“行测”“讲义上的原题”和多数“声誉”的识别更稳定；Paraformer 出现“声育”“蒋一生”“雪习”等明显错词。两者都对部分“速算/首句”存在同音误写。用户完成人工审阅后确认 Qwen3 为无字幕视频默认在线候选。详细数据与代表性错误见成果目录中的 `对比说明.md`。

本次没有传 `language` 参数，但 Qwen3 原始结果已将全部 110 个句段自动标记为 `zh`。官方的 `language=zh` 只提示中文语种，不选择东北方言；Qwen3 公开中文范围没有单列东北话。因此保持自动语种识别，避免对中外语混合课程造成限制。东北口音造成的同音词问题先由当前模型承担，只有完整课程反复出现关键术语错误时才重新评估带地区官话或热词能力的模型。

厂商返回用量分别为 Qwen3 `seconds: 469`、Paraformer `duration: 559`，按公开原价估算合计约 0.14790 元，低于按完整音频估算的 0.18 元保守上限。两项均有用户确认的免费额度，实际扣减需以控制台刷新后的数据为准。调用中产生三个 Paraformer/Qwen3 模型绑定的临时私有副本，其中一个是网络异常后的未引用副本；它们均不备份，预计 48 小时后失效。
